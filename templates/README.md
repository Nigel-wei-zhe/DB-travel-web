# Google 試算表 CSV 範本

將三個 CSV 分別匯入同一份 Google 試算表的 `trip`、`itinerary`、`shops` 工作表。第一列是固定中文欄名；從第二列開始填資料，不要更改欄名或順序。檔案只有欄名，沒有示範資料。同步程式會讀取這三個工作表，產生 `data/itinerary.jsonl` 與 `data/shops.jsonl`。網站不能直接讀 CSV。

## 旅行設定：trip.csv

只填一列。「旅程ID」、「旅程名稱」、「時區」、「貨幣」必填；例如時區用 `Asia/Tokyo`，貨幣用 `JPY`。「副標題」可留空。首頁要顯示目的地並取得當地天氣時，「目的地名稱」、「目的地國家」、「目的地緯度」、「目的地經度」四欄一起填；不填則四欄全部留空，網站會以第一天的地點座標取得天氣。

## 每日行程：itinerary.csv

每個行程項目一列。同一天的「日期」、「當日標題」、「當日地點」、「當日緯度」、「當日經度」每列都要重複填寫且內容一致。沒有行程項目的日期也要填一列，前五欄填好，「行程ID」到「行程經度」全部留空，網站才會顯示「尚未安排行程」。

「日期」固定填 `YYYY-MM-DD`，例如 `2026-11-12`；「時間」固定填 24 小時制 `HH:mm`，例如 `09:05`，可留空表示彈性。請在試算表中將日期、時間和各 ID 欄設為「純文字」，避免匯出時格式改變。「當日緯度」、「當日經度」是當日城市座標，必填數字；「行程緯度」、「行程經度」是該行程地圖圖釘座標，可一起留空，不能只填其中一欄。

有行程項目的列，「行程ID」、「行程名稱」必填。「分類」可填 `transport`（交通）、`sightseeing`（景點）、`food`（飲食）、`shopping`（購物）、`stay`（住宿）、`other`（其他），也可留空。「備註」與「地圖搜尋文字」可留空；後者填可供 Google 地圖搜尋的地點文字。列的先後順序就是同一天網站顯示的順序，日期則由網站自動排序。

## 精選店家：shops.csv

每間店家一列。同一群組的「區域ID」、「區域名稱」每列都要重複填寫且內容一致。沒有店家的群組也要填一列，前兩欄填好，「店家ID」到「地圖搜尋文字」全部留空。

有店家的列，「店家ID」、「店家名稱」必填。「類型標籤」用半形直線 `|` 分隔多個標籤，例如 `咖啡|甜點`；不需要標籤可留空。「備註」、「地圖搜尋文字」可留空。群組依第一次出現的順序顯示，組內店家依列順序顯示。

## 同步程式的轉換規則

1. 讀取 CSV 時依標準 CSV 規則處理引號、逗號與儲存格內換行；忽略完全空白的列。
2. `trip.csv` 須恰有一筆資料，轉成 `itinerary.jsonl` 第一行的旅行設定；非空白的目的地四欄組成 `destination` 物件。
3. `itinerary.csv` 至少要有一天。依「日期」分組，檢查同日的標題和地點欄一致；行程項目保留原列順序。行程欄位全空的列產生空行程，不能與同日的實際項目並存。
4. `shops.csv` 依「區域ID」分組，檢查同群組的「區域名稱」一致；店家保留原列順序。「類型標籤」以 `|` 拆開並去除前後空白。空店家列不能與同群組的實際店家並存。
5. 空白的選填欄位直接省略。座標轉成數字。輸出 UTF-8 JSONL 前會用 `trip-data.js` 驗證，驗證失敗就停止，不覆蓋原本的 JSONL。

同一趟旅行請保留原本的「旅程ID」和既有行程的「行程ID」，才會延續本機蓋章紀錄。新旅行再建立新 ID。試算表設為「知道連結的都能檢視」後，連結持有者即可讀取內容；同步後 JSONL 也會公開在網站，請勿放訂房代碼、私人電話等敏感內容。完整 JSONL 規則見 [`data/FORMAT.md`](../data/FORMAT.md)。

## 執行同步

在 GitHub Repository secrets 建立 `sheet_url`，值為這份 Google 試算表的完整網址。試算表需設為「知道連結的都能檢視」，三個工作表名稱固定為 `trip`、`itinerary`、`shops`。推送到 `dev` 時，「同步 Google 試算表」流程會讀取資料，驗證後提交更新。試算表編輯本身不會觸發 GitHub Action。工作流程進入儲存庫的預設分支後，也能在 Actions 頁面選擇 `dev` 手動執行。

目前 GitHub Pages 從 `dev` 分支部署。GitHub 的 `GITHUB_TOKEN` 所推送的提交不會觸發 Pages 建置。若希望同步後直接更新正式網站，需另建 Repository secret `PAGES_PUSH_TOKEN`，放入具有此儲存庫 Contents 寫入權限的個人存取權杖；流程會優先使用它推送。未設定時，資料仍會提交到 `dev`，但要另外由有權限的使用者推送至 `dev` 才會更新正式網站。
